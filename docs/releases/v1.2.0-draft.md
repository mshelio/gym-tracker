# Gym Tracker v1.2.0 — draft GitHub release notes

**Status: prepared, not published.** Target: the main commit after merging the release-readiness PR, subject to passing post-merge workflows.

This release expands Gym Tracker from workout logging into calendar planning and muscle-specific analysis without changing its local-first storage model.

## What's new
- **Training calendar:** Browse month and week views, see logged sessions, planned training, rest and explicit skipped events. Adherence uses recorded outcomes; missing historical dates are not retroactively treated as missed workouts.
- **Exercise taxonomy:** Recognized exercises and common alternatives have stable catalog IDs, primary and secondary muscle groups, and equipment metadata. User-defined and unknown names remain supported.
- **Muscle-group analytics:** See weekly primary hard sets and volume by muscle, with separately reported half-credit secondary muscle contributions and an Unknown bucket. Warm-up/incomplete sets are excluded; valid drop sets count toward volume but not hard sets.
- **Large-history performance:** Improved Progress calculations and chart downsampling validated against realistic 1,000- and 10,000-session fixtures without truncating analytical totals.

## Data and privacy
Data is still kept in browser IndexedDB, and snapshots continue to use transactional revision checks. The downloadable backup stays at **version 4** and older backup imports remain supported. Calendar events are optional. The app does not introduce cloud sync, an account requirement or automatic uploading of workout data.

## Upgrade and recovery guidance
Before upgrading, **export a fresh JSON backup** from Data. After deploying, verify the PWA's **Update now** prompt if an update is waiting; avoid clearing site data unless a recoverable backup is available. Reload and check the Calendar, Progress analytics and existing workouts. To downgrade, keep an up-to-date export: older versions may not support every newer backup field.

## Release validation
Release candidate must pass regression tests, cross-browser Playwright, production Pages deployment, live PWA smoke, v4 schema consistency and the deterministic service-worker revision check at the exact candidate SHA.
