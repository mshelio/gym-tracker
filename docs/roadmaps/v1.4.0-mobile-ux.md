# Gym Tracker v1.4.0 — Mobile-first UI/UX modernization

**Status:** Proposed plan only. No app behavior, database, tag or release changes in this planning PR.

## Release objective

Make the local-first Gym Tracker fast, cohesive, and pleasant to use on iPhone, Android and desktop with **adaptive light and dark themes**. v1.4.0 does **not** introduce accounts, server-side APIs, cloud sync or AI assistance.

## Architecture audit (current main)

- `index.html` contains the desktop navigation shell and an app-root region. `css/styles.css` uses semantic-ish CSS variables for a **light-only** scheme (`color-scheme:light`) with hardcoded colors throughout; `css/muscle-map.css` has separate SVG and forced-colors styles.
- `js/app.js` is a large ~103 KB central event/render controller composing modular state, timers, schedules, analytics, exercise search, history edits, IndexedDB and PWA support. UI work must be incremental; avoid rewriting persistence and attribution logic.
- `js/state.js` holds in-memory screen/training state; `js/storage.js` persists locally in IndexedDB. Theme settings must not silently change the backup v4 schema. A separate UI preference is acceptable only if its persistence and backup policy is explicitly tested.
- `js/pwa.js` inserts a visually hardcoded bottom-right banner that needs theming and mobile-safe placement. The app uses a versioned offline service worker; any modified precached asset requires deterministic SW hash regeneration.
- Existing five Playwright projects cover desktop Chromium/Firefox/WebKit and mobile Chromium/WebKit; preserve these and expand representative visual, accessibility and offline journeys.
- `README.md` still describes v1.3.0 as unreleased; reconcile against an independently verified published tag/release in a housekeeping PR, not by assuming publication from chat confirmation.

## Visual design specification

- Default: follow `prefers-color-scheme`; explicit System / Light / Dark user preference with stable reload and installed-PWA behavior.
- Create semantic foreground/background, surface/elevation, border, status, chart/muscle-map and focus tokens; colors must encode meaning alongside text/icon shapes. Provide WCAG 2.2 AA contrast, 200% zoom, forced-colors mode and reduced-motion support.
- Use a clear typography scale, 8px-derived spacing tokens, accessible input/error/status patterns, safe-area padding and 44×44 CSS-pixel preferred mobile interactive targets.
- Maintain intuitive platform conventions: bottom navigation and one prominent Start/Continue Workout action on compact screens, desktop rail on wide screens; content and controls should remain discoverable without unnecessary navigation.
- Do not use new remote image/font/CDN dependencies: retain offline installability and GitHub Pages repo-subpath paths.

## Release acceptance gates

- Full regression suite and Playwright Chromium, Firefox, WebKit, mobile Chromium and mobile WebKit green; compare representative light/dark, reduced-motion and forced-colors scenarios.
- Existing charts, statistics, primary/secondary muscle attribution and contributing-exercise breakdown remain numerically identical for the same data and filters.
- IndexedDB atomic writes, revisions, draft autosave, completed-session edits, schedule progression and workout timers remain correct on reload, offline and failed writes.
- Backup import compatibility for v1–v4; v4 export/restore round-trip; no implicit schema migration or deletion of real stored data.
- GitHub Pages deployed domain loads from `/gym-tracker/`; PWA fresh install and in-place upgrade checked, retaining workout drafts/history; updated app assets are precached with the correct service-worker revision.
- Keyboard-only, screen-reader (including iPhone VoiceOver), touch, focus management, 200% zoom, high contrast and reduced motion smoke results recorded; no blocking WCAG AA findings in changed workflows.
- Tagging/releasing only after final commit validation and separate explicit user authorization.
