# Gym Tracker v1.3.0 — Muscle Visualization Roadmap

> **Status:** Proposed, not yet implemented. **Tracking:** [Issue #81](https://github.com/mshelio/gym-tracker/issues/81). No release is authorized by this document.

## Goal

Transform the existing v1.2.0 muscle-group analytics into a responsive, accessible anatomical front/back muscle heatmap. Keep Gym Tracker fully local-first and preserve existing analytical definitions, IndexedDB snapshots and JSON v4 backups.

## User-facing scope

1. **Front/back interactive maps:** selectable muscle regions on self-hosted SVG diagrams, accessible by keyboard, pointer and touch.
2. **Two metric modes:** primary hard sets and primary training volume; secondary half-credit contributions reported separately rather than mixed into primary totals.
3. **Period filtering:** existing inclusive date range plus week/month shortcuts where consistent with Progress.
4. **Detail panel:** muscle name, primary hard sets, secondary contribution, volume, and contributing exercises.
5. **Exercise activation view:** optional primary/secondary region highlighting on recognized exercises; show Unknown for unmapped exercises.
6. **Transparent visualization:** documented relative color scale with neutral zero/unknown, explanatory legend, and exact numerical table fallback. Colors are *training workload*, never muscle growth or recovery.

## Technical decisions

- Use static SVG assets embedded or bundled locally; no runtime third-party dependency.
- License-check and attribute any anatomical artwork before committing.
- Map existing canonical muscle taxonomy IDs to explicit SVG region IDs; do not infer classifications for unknown/custom movements.
- Derive display values from the established v1.2.0 analytics pipeline.
- Respect warm-up/incomplete exclusion, valid drop-set volume but not hard sets, primary exclusivity and separate half-credit secondary attribution.
- Handle historical edits/deletes, backup imports, date filters and kg/lb units without stale cache.
- Do not alter persisted session shape, backup v4, schedule progress or storage transactions.
- Precache any new static assets with the versioned service-worker process.

## Delivery plan

### Phase A — Data and mapping
- Inventory exercise metadata, muscle identifiers and Progress filters.
- Define anatomical region mapping and pure adapter, unknown handling and numerical legend domains.
- Unit tests for aggregation, units, empty data and edited history.

### Phase B — Visualization and accessibility
- Design/install licensed front and back SVGs.
- Build clickable/focusable region overlays, accessible labels and selection state.
- Build compact filter controls, legend, selected-muscle detail view and data table.
- Responsive/mobile styles, reduced motion and high-contrast support.

### Phase C — Integration and QA
- Optional exercise-level activation highlighting.
- Verify offline/PWA precache and no migration.
- Regression plus Chromium, Firefox, WebKit and mobile Playwright tests.
- Verify GitHub Actions, GitHub Pages deployment and production PWA smoke before release consideration.

## Exit criteria

See issue #81 for the complete acceptance checklist. Feature completion requires all essential criteria and browser tests passing; merging a planning document does **not** imply feature completion.

## Release boundaries

**v1.3.0:** 2D muscle maps + training heatmap and accessibility, alongside already planned PWA reliability work.

**Not in v1.3.0:** cloud synchronization, AI coaching, 3D/WebGL muscle maps, recovery prediction or anatomical/medical assertions.
